# 標準工作流

## 總覽

Codex PPT 的工作流強調階段確認。它不會一開始直接產生整套 PPT，而是先確認大綱、風格、圖片後端和範例投影片，降低返工成本。

## 階段 1：閱讀輸入材料

agent 會先理解：

- 主題和核心觀點
- 目標受眾
- 演示目標
- 頁數要求
- 必須包含或排除的內容
- 是否有必需圖片素材

## 階段 2：確認大綱

agent 會產生 `outline.md`，通常包括：

- Slide 編號
- 每頁標題
- 3-5 個要點
- 頁面角色，如封面、目錄、概念解釋、流程、對比、資料證據、總結等
- 可選視覺想法
- 必需圖片素材及其用途

大綱確認前，不應產生正式 slide 圖片、`speech.md` 或 `.pptx`。

## 階段 3：確認視覺風格

agent 會給出 2-3 個風格方向並推薦一個。候選風格來自 12 種內建風格（清爽專業風、學術口試風、手繪技術解說風、麥肯錫風格、政務紅風格、教學教材風等）和你的個人風格庫，也可以基於你提供的截圖、PDF 或 PPT 重現風格。完整風格預覽參見[風格與個人風格庫](styles.md)。

選擇風格後，整套 PPT 應保持統一視覺語言，但每頁版式可以根據內容變化。

## 階段 4：確認圖片產生後端

優先使用 Codex 內建圖片產生工具。只有在內建工具不可用、使用者明確要求 API/CLI fallback，或當前能力無法滿足時，才切換到 `scripts/image_gen.py`。

圖片後端確認後，整套 PPT 應保持一致，不應中途切換。

## 階段 5：產生並確認範例投影片

先產生 1 頁範例投影片，檢查：

- 文字是否清晰
- 風格是否符合預期
- 頁面密度是否合適
- 色彩和排版是否穩定
- 是否適合批次擴充套件到整套 PPT

範例投影片透過後，再批次產生整套。

## 階段 6：批次產生

範例投影片確認後，agent 會逐頁產生 `origin_image/slide_XX.png`。在支援子代理的環境中，會由一個子代理負責一頁並行產生，加快多頁產出；所有頁面沿用範例投影片確認的同一風格和同一圖片生成後端。

## 階段 7：品質檢查與修復

組裝前，agent 會逐頁檢查文字清晰度、與大綱的一致性、內容截斷、風格統一性、多餘頁碼和元素重疊等問題。發現嚴重問題的頁面會用更嚴格的提示詞重新產生，局部小問題優先用圖片編輯能力定向修復。

## 階段 8：演講稿與組裝

產生 `speech.md` 演講稿，然後用 `assemble_ppt.py` 組裝成 `.pptx`，演講稿會自動寫入每頁 PPT 的備註區。

## 階段 9（可選）：儲存風格

如果這套 PPT 用的是自訂或調整過的風格，agent 會在最終報告裡提示你可以把風格儲存到個人風格庫，以後直接按名字重複使用。參見[風格與個人風格庫](styles.md)。
