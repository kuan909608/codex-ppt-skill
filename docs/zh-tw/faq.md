# 常見問題

## Q：產生的是可編輯 PPT 嗎？

不是。Codex PPT 產生的是圖片式 PPT，每一頁是一張完整投影片圖片。視覺效果更統一，但頁面裡的文字、圖表、形狀不能像傳統 PPT 那樣逐項編輯。產生完成後，如果需要調整內容或視覺效果，推薦直接在同一段對話裡繼續讓 AI 修改具體頁面。

如無必要，請不要轉成可編輯 PPT，除非你 Codex 額度充足。

如果需要進一步轉換成可編輯 PPT，可以在產生後嘗試使用 [image-to-editable-ppt-skill](https://github.com/ningzimu/image-to-editable-ppt-skill)。不過 `image-to-editable-ppt-skill` 目前屬於測試版本，且目前只支援 ChatGPT Plus / Pro 會員在 Codex 中使用，不支援其他 agent。如果效果不穩定，請等待後續更新通知。

注意：圖片轉可編輯 skill 目前消耗 token 較多，對 Plus 使用者不太適合，Pro 使用者隨意。

## Q：支援其他 agent 嗎？

支援。Codex PPT 本身是基於 `SKILL.md` 的 skill，除了 Codex，也可以在 Claude Code、OpenClaw、Hermes Agent 等支援 `SKILL.md` 的 agent 中使用。

本 skill 在 Codex 場景下開發和測試，對 Codex 的適配度最好，推薦優先使用。

需要注意的是，不同 agent 的圖片產生能力和工具介面不一樣。如果不是在 Codex 中使用，通常需要設定 `gpt-image-2` 或第三方 OpenAI 相容格式的圖片生成 API。具體設定方式可以參考[安裝與設定](installation.md)，並在使用過程中讓 AI 根據當前環境引導完成。

## Q：如何更新 skill 到最新版本？

重新執行一遍安裝命令即可覆蓋為最新版本，或者直接讓 agent 幫你更新，然後重啟 agent 生效。API key 設定和個人風格庫都存放在 skill 安裝目錄之外，更新不會丟失。具體命令參見[安裝與設定](installation.md)。

## Q：為什麼第一張範例投影片不錯，後面的頁面又變差或風格不一樣？

這通常說明“範例投影片風格”沒有被穩定傳遞到後續頁面，或者後續頁面在產生時換了提示詞、換了後端、換了子代理執行方式。

正常情況下，範例投影片確認後，後續頁面應該繼承同一套視覺語言，包括配色、字型氣質、版式密度、插畫方式和圖片產生後端。如果後面頁面明顯偏離，可以讓 AI 檢查：是否把範例投影片作為風格參考傳給每一頁；是否記錄並沿用了同一個圖片生成方式；子代理有沒有擅自換成別的產生方式；每頁提示詞是否過於寬泛。

建議處理方式是：不要整份重新製作，先挑 1-2 頁明顯偏離的頁面，讓 AI 對照已確認範例投影片重新產生，並明確要求“保持範例投影片的視覺風格、同一圖片產生後端和同一版式密度”。

## Q：產生的 PPT 很醜怎麼辦？

請先檢查自己的 `gpt-image-2` 模型是否可以正常圖片生成。如果模型本身不可用、返回品質異常，或者第三方 API / 轉接服務沒有正確支援 `gpt-image-2`，產生效果會明顯變差。

確認模型可用後，再讓 AI 針對具體問題修改，例如風格不統一、文字太小、頁面太擠、配色不好看、插圖不貼合主題等。建議先重新產生 1 頁範例投影片，滿意後再繼續整套產生。

## Q：產生的投影片圖片比較模糊怎麼辦？

Codex 會員預設使用內建圖片生成工具，其產生的圖片解析度比較低，且目前不能手動指定解析度。如果需要更高解析度的影像，需要改用 `gpt-image-2` API 的方式產生（即 API/CLI fallback，設定 API key、base URL 和模型名，參見[安裝與設定](installation.md)）。

API/CLI fallback 場景下，指令碼預設解析度是 2K 16:9 橫屏。如果圖片仍然模糊，尤其是文字較多的頁面，可以讓 AI 改用 4K 解析度產生。

## Q：為什麼要先確認大綱？

因為 PPT 的返工成本主要來自結構問題。先確認頁數、標題、順序和每頁要點，可以避免後面圖片都產生完了才發現內容方向不對。

## Q：為什麼要先產生範例投影片？

範例投影片是整套 PPT 的視覺基準。確認範例投影片後，後續頁面可以繼承同一套配色、字型氣質、密度和視覺語言。

## Q：Codex 裡需要設定 API key 嗎？

如果 Codex 內建圖片產生工具可用，通常不需要設定 API key。只有在選擇 API/CLI fallback 時，才需要設定 `OPENAI_API_KEY`、可選 `OPENAI_BASE_URL` 和模型名。

## Q：可以插入論文原圖或架構圖嗎？

可以。建議在大綱階段明確圖片對應的頁碼和用途，並說明它是嚴格輸入素材還是風格參考。對於論文圖、實驗結果圖、截圖和架構圖，應儘量保留原始資訊、標籤、座標軸、數值和箭頭關係。

## Q：某一頁效果不好怎麼辦？

優先只修改這一頁。告訴 agent 具體問題，例如文字太小、層次不清、配色不適合、圖太擁擠或某個概念表達不準確。

## Q：可以儲存自己的風格嗎？

可以。把喜歡的 PPT 截圖、PDF 或完整 PPT 交給 agent 分析，產生滿意後，可以讓 agent 把這套風格儲存到個人風格庫（`~/.codex-ppt-skill/references/`）。風格庫存放在 skill 安裝目錄之外，更新或重灌 skill 都不會丟失；如果與內建風格同名，個人風格優先。詳見[風格與個人風格庫](styles.md)。
