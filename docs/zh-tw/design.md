# 設計理念

Codex PPT Skill 裡面放了我對 AI 做 PPT 的一些思考。

AI 做 PPT 最重要的不是快，而是流程可控，做出來可用。

所以我把流程拆成了幾步：

1. 讀文章、論文、報告或 Markdown
2. 產生大綱，讓使用者確認頁數、標題和每頁重點
3. 再確認整體視覺風格
4. 產生 1 頁範例投影片，看文字、版式和風格是否符合預期
5. 範例投影片確認後，再逐頁產生整套圖片式 PPT
6. 最後組裝成 `.pptx`，並把講稿寫進備註裡，方便對照講解

## 為什麼預設先做圖片式 PPT？

因為不是所有場景都需要可編輯。如果只是技術分享、課程筆記、讀書分享、論文解讀或不那麼正式的報告，整頁圖片式 PPT 其實已經夠用，而且視覺統一性更好。

如果一開始就把“產生 PPT”和“轉可編輯 PPT”強行耦合在一起，流程會變得很重：前期還在反覆改大綱、改風格、改範例投影片，就引入編輯結構還原，反而更慢、更貴、更難控。

所以我把它拆成兩個 skill：

- 一個負責產生高品質圖片式 PPT
- 另一個負責在需要時，把純圖 PPT 再轉換成可編輯 PPT

先把內容和視覺方向聊清楚，確認產生結果可控，再考慮要不要轉成可編輯，我覺得更穩。

## 針對社群反饋做的最佳化

這個 skill 裡還做了一些針對社群反饋的最佳化：

- 支援 Codex 會員內建圖片生成能力
- 也支援透過 API 接入圖片生成模型
- 可以在 Codex、Claude Code、OpenClaw 等 agent 環境中使用
- 支援子代理並行產生，加快多頁 PPT 產出
- 內建多種風格引導，不會寫高階 prompt 也能做出還不錯的效果
- 支援參考圖片、已有 PPT，產生類似風格的新 PPT
- 對論文圖、實驗結果圖、截圖這類使用者原始圖片做了保留最佳化，儘量避免 AI 重新亂畫

我想做的不是“點一下出一個 20 頁的 PPT”，而是把 AI 做 PPT 這件事變成一個更像真實工作流的過程：先確定結構，再確定風格，再確認範例投影片，最後批次產生和自檢。
